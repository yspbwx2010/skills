# Symbol trimming, module signing and the GKI symbol gate

Facts are for OGKI `android15-6.6` (Linux 6.6.118) built with plain Kbuild from `gki_defconfig`. Every
"this build" statement is config-dependent: re-run the check command on your own `$KERNEL_OUT`.

## 1. `CONFIG_TRIM_UNUSED_KSYMS`

### 1.1 How 6.6 trims (in modpost)

Defined in `kernel/module/Kconfig`; its help text ends with the warning that matters here:
`If unsure, or if you need to build out-of-tree modules, say N.`

6.6 no longer uses the old `autoksyms.h` rebuild loop (`scripts/gen_autoksyms.sh` and
`scripts/adjust_autoksyms.sh` are gone). Trimming happens in modpost:

1. `scripts/Makefile.modpost`: with TRIM on, modpost gets `-t`, plus `-u <file>` for
   `CONFIG_UNUSED_KSYMS_WHITELIST`.
2. `scripts/mod/modpost.c`: `-t` sets `trim_unused_exports`; `handle_white_list_exports()` marks every
   whitelisted symbol `used`; any export an in-tree module imports is also marked `used`.
3. When writing `.mod.c`, an export with `!sym->used` gets **no `KSYMTAB_*` entry and no CRC**. It is also
   left out of `Module.symvers`.

Result: the function body still exists (visible in `/proc/kallsyms` with `CONFIG_KALLSYMS_ALL=y`) but
there is no ksymtab entry, so there is no legitimate way to link to it:

- building an external module against a trimmed `Module.symvers`: `modpost: "<sym>" [...] undefined!`
- loading a module built elsewhere: `Unknown symbol <sym>`

Enabling TRIM also forces the in-tree modules to be built along with vmlinux (`KBUILD_MODULES := 1` in the
top-level `Makefile`), because modpost must see which symbols they use.

### 1.2 State in this build (verified)

```sh
grep -n 'TRIM_UNUSED_KSYMS\|UNUSED_KSYMS_WHITELIST' "$KERNEL_OUT"/.config
# -> # CONFIG_TRIM_UNUSED_KSYMS is not set
#    (no CONFIG_UNUSED_KSYMS_WHITELIST line: it depends on TRIM)
```

`gki_defconfig` contains neither option. Official builds enable trimming from Kleaf
(`trim_nonlisted_kmi = True` in `BUILD.bazel`), not from the defconfig, so a plain
`make gki_defconfig` build never trims.

### 1.3 Consequences

- All 16923 exports in `Module.symvers` are usable, including 746 `__tracepoint_android_*` hook symbols
  (all `EXPORT_SYMBOL_GPL`). About 7.7k of those exports are outside the KMI lists
  ([architecture.md](architecture.md) section 4.3).
- Non-KMI exports carry no stability promise: they can disappear or change signature at the next ACK
  merge. A module using them is tied to this tree and commit.
- **Turning trimming off does not free you from the KMI.** The stock vendor modules on the device still
  bind to KMI symbols, CRCs and type layouts; anything you change there still breaks them.
- Adding an export (`EXPORT_SYMBOL_GPL`) does not by itself break existing modules.
- Minor: an untrimmed `vmlinux` is slightly larger. Irrelevant for LTO here (`CONFIG_LTO_NONE=y`).

## 2. Module signing and `CONFIG_MODULE_SIG_PROTECT`

### 2.1 Config in this build

| Option | Value |
|---|---|
| `CONFIG_MODULE_SIG` | y |
| `CONFIG_MODULE_SIG_FORCE` | **n** |
| `CONFIG_MODULE_SIG_PROTECT` | y |
| `CONFIG_MODULE_SIG_ALL` | y |
| `CONFIG_MODULE_SIG_HASH` | `"sha1"` |
| `CONFIG_MODULE_SIG_KEY` | `"certs/signing_key.pem"` |
| `CONFIG_SECURITY_LOCKDOWN_LSM` | n |
| `CONFIG_MODULE_FORCE_LOAD` | n |

`MODULE_SIG_PROTECT` `depends on MODULE_SIG && !MODULE_SIG_FORCE`: it and forced signing are exclusive.

### 2.2 What `MODULE_SIG_PROTECT` changes

An Android-only mechanism (`kernel/module/Kconfig`). It turns the signature from an admission check into an
identity label: signed = GKI module, unsigned = vendor module.

1. **Unsigned modules are never rejected.** `kernel/module/signing.c`: with PROTECT, `sig_enforce` is the
   constant `false`, and an unverified module returns 0 without even the lockdown check.
2. **Unsigned modules may only resolve (a) symbols exported by other unsigned modules and (b) unprotected
   symbols.** `kernel/module/main.c`, in `resolve_symbol()`:
   ```c
   is_vendor_module = !mod->sig_ok;
   is_vendor_exported_symbol = fsa.owner && !fsa.owner->sig_ok;
   if (is_vendor_module && !is_vendor_exported_symbol &&
       !gki_is_module_unprotected_symbol(name)) {
           fsa.sym = ERR_PTR(-EACCES);   /* dmesg: "<mod>: Protected symbol: <sym> (err -13)" */
           goto getname;
   }
   ```
3. **Unsigned modules may not export a symbol that a GKI module exports.** Same file,
   `verify_exported_symbols()`: `"<mod>: exports protected symbol <sym>"`, `-EACCES`. Names come from
   `android/abi_gki_protected_exports_aarch64` (507 symbols).

Both lookups live in `kernel/module/gki_module.c` and `bsearch` two tables generated at build time.

### 2.3 Finding: the gate is empty in this build (verified)

The tables are generated by `scripts/gen_gki_modules_headers.sh`. The "unprotected" input is chosen in
`kernel/module/Makefile`:

```make
ifneq ($(CONFIG_UNUSED_KSYMS_WHITELIST),)
ALL_KMI_SYMBOLS := $(CONFIG_UNUSED_KSYMS_WHITELIST)
else
ALL_KMI_SYMBOLS := include/config/abi_gki_kmi_symbols
$(ALL_KMI_SYMBOLS):
	: > $@
endif
```

With no whitelist (section 1.2) the input is an empty file, and the generated header is an empty array
(`NR_UNPROTECTED_SYMBOLS == 0`). `gki_module.c` then takes its fallback in both functions:

- `gki_is_module_unprotected_symbol()` returns **true** for every name ("there isn't a KMI enforcement
  for the kernel. Treat everything accessible in this case.");
- `gki_is_module_protected_export()` returns **false** for every name.

So in this build `CONFIG_MODULE_SIG_PROTECT=y` does nothing. An unsigned out-of-tree module can resolve
**any** of the 16923 exports and may export names on the 507-symbol protected list. The chain follows from
the config, not from one build's artefacts. Verify on your build:

```sh
grep -A1 'gki_unprotected_symbols\[\]' "$KERNEL_OUT/include/generated/gki_module_unprotected.h"
# next line "};" => empty table => gate open
```

(Inferred, not verified on a stock image) An official build passes the KMI union as the whitelist, the
table is non-empty, and unsigned vendor modules are limited to KMI symbols. Every "freedom" in this file
reverses on such a kernel.

### 2.4 When signing happens: your module is not signed

`CONFIG_MODULE_SIG_ALL=y` signs only during `modules_install` (`scripts/Makefile.modinst`: "During
modules_install, modules are signed only when CONFIG_MODULE_SIG_ALL=y"). `make ... M=<dir> modules` does
not sign. Such a `.ko` has no `~Module signature appended~` trailer, so `mod->sig_ok == false` and it is a
vendor module:

```sh
tail -c 28 mymod.ko | strings        # no "~Module signature appended~" => unsigned
```

The key `certs/signing_key.pem` is generated by `openssl req ... -x509 -days 36500` during the build
(`certs/Makefile`). It is a throwaway self-signed key, not Google's or an OEM's, and is regenerated after
`make mrproper`.

- You **can** sign: `scripts/sign-file sha1 certs/signing_key.pem certs/signing_key.x509 mymod.ko`
  (run in `$KERNEL_OUT`).
- On this build it gains nothing (the gate is empty) and moves the module to the "GKI module" side of the
  `is_vendor_exported_symbol` test. Not recommended (inferred; no signed-vs-unsigned comparison was run).
- `CONFIG_MODULE_SIG_HASH="sha1"`: whether some environment rejects SHA-1 signatures was not checked;
  with signing unenforced the impact is small.
