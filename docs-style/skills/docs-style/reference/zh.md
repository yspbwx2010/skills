# 中文技术文档补充

主 skill 按谷歌开发者文档风格指南写英文. 写中文技术文档时读这份: 它补中文特有的部分, 并取代只针对英语句子的规则 (缩略形式, 冠词, this 后跟名词, 英文标点和拼写). 与语言无关的规则照常适用: 不编造事实, 成篇框架, 主动语态, 祈使句, 先条件后动作, 一句一事. 冲突时的顺序不变: 项目规矩和作者语气优先, 其次本文件, 再其次主 skill

本文自己的行文就用默认的档案 B, 可以直接当样例. 全角标点只出现在档案 A 的说明, 示例和 "错" 示例里

## 标点档案

默认用档案 B. 项目或作者的规则 (风格文件, `AGENTS.md`, `CONTRIBUTING.md`) 声明用档案 A 时, 改用档案 A. 选定后全文只用一档, 不混用. 从 [中英文与数字之间的空格](#中英文与数字之间的空格) 一节起的规则对两档都成立

### 档案 B (默认)

参照作者公开 skill 仓 yspbwx2010/skills 里各个 skill 的 `README.md`

- 标点全部半角, 前面不加空格, 后面跟一个空格: `, ` `: ` `; ` `? ` `! `
- 段内要分句时用 `. `, 后面同样跟一个空格
- 段落, 列表项, 表格单元格末尾都不加句号. 列表项是完整句子时也不加
- 括号用半角, 括号外侧与中文之间加空格: `让你的 Agent 会用 mcpp (一个构建工具) 构建`
- 引号用半角直引号 `"..."`, 外侧与中文之间加空格: `这类 "私有" 类型`
- 不用破折号, 改用逗号或括号. 错: `缓存目录——默认在 target 下——可以改` → 对: `缓存目录 (默认在 target 下) 可以改`
- 省略号写 `...`, 只偶尔用
- 并列项用逗号, 不用顿号. 错: `构建、测试、发布` → 对: `构建, 测试, 发布`
- 二选一的两项之间可以写 ` / `: `Android / 桌面`
- 汉字与英文字母, 汉字与数字之间照常加空格, 见 [中英文与数字之间的空格](#中英文与数字之间的空格)

示例 (命令在真实文档里放代码字体): `运行 mcpp build, 然后检查 target 目录 (路径见下一节)`

### 档案 A (主流中文排版)

项目或作者声明用档案 A 时才用. 下面的示例保留全角:

- 中文句子里用全角标点: `，。、：；？！（）`
- 句子里夹英文词, 代码, 数字时, 标点仍按所在句子的语言: 中文句用全角, 整句英文或整段引用英文用半角
- 全角标点与前后文字之间不加空格
- 引号用 `“ ”`, 嵌套用 `‘ ’`, 文档标题用 `《》`; 省略号用 `……`, 破折号用 `——`
- 段落结尾加句号; 列表项是完整句子时加句号, 是短语时不加
- 并列的中文词语可以用顿号

示例 (命令在真实文档里放代码字体): `运行 mcpp build，然后检查 target 目录（路径见下一节）。`

### 两档的边界

- 中文句子引用一整句英文时, 引文保留它自己的标点, 两档都是这样. 档案 B 的 "段尾不加句号" 管不到引文里面. 错: `上游文档只写了一句 "Builds are cached per configuration"` (删掉了原句的句号) → 对: `上游文档只写了一句 "Builds are cached per configuration."`
- 档案 B 里, 半角句号会和文件名, 小数点混淆. 句末是文件名时改写句子, 或把文件名放进代码字体. 错: `编辑 mcpp.toml. 然后重新构建` → 对: `` 编辑 `mcpp.toml`. 然后重新构建 ``
- 档案 A 里, 全角标点紧贴 URL 会被部分渲染器吞进链接. 错: `详见 https://example.com/a，其中...` → 对: `详见 [发布说明](https://example.com/a)，其中...`
- 两档都不要手工在 Markdown 里按 80 列折行, 除非仓库本身这样写. 多数渲染器会把换行变成空格, 汉字之间多出一个缝. 一个段落写在一行里
- 两档都不要在代码块或代码字体里使用全角标点或弯引号, 复制出去的命令会直接坏掉. 错: `git commit -m “fix”` (弯引号) → 对: `git commit -m "fix"`

## 中英文与数字之间的空格

两档都要求: 汉字与英文字母, 汉字与阿拉伯数字之间加一个空格

- 错: `使用mcpp构建C++23项目` → 对: `使用 mcpp 构建 C++23 项目`
- 错: `第8代KMI` → 对: `第 8 代 KMI`
- 代码字体前后遇到汉字也加空格. 错: `` 运行`mcpp test`检查 `` → 对: `` 运行 `mcpp test` 检查 ``
- 例外: 数字与 `%`, `°` 之间不加空格, 如 `88%`, `90°`
- 例外: 档案 A 的全角标点与前后文字之间不加空格. 档案 B 的半角标点前面不加空格, 后面加一个
- 例外: 专有名词内部的写法照官方, 如 `GitHub`, `C++23`, 不要拆开
- 链接文字也一样: `[发布说明](...)` 前后遇到汉字要加空格

## 产品名, 命令, 文件名, 代码

本节规定产品名, 可执行内容和占位符怎么写, 下面分四类

### 产品名照官方写法, 不音译, 不改大小写

- 错: `github`, `Github`, `MacOS` → 对: `GitHub`, `macOS`
- 错: `NPM` (官方是小写) → 对: `npm`
- 不音译, 不用昵称. 写 Chrome 功能时, 错: `谷歌浏览器的开发者工具` → 对: `Chrome DevTools`
- 名字不当动词, 不加后缀. 错: `git 一下`, `docker 化` → 对: `用 Git 提交`, `放进 Docker 容器里运行`
- 产品名后面要不要跟类别词: 第一次出现可以写 `mcpp 构建工具`, 之后只写 `mcpp`. 不要每次都带
- 官方写法是小写开头的名字 (`npm`, `iOS`) 不要放在句首被迫改大写, 改写句子. 错: `Npm 会读取 package.json` → 对: `用 npm 安装时会读取 package.json`

### 命令, 文件, 路径, 标志, 环境变量, 函数, 配置键一律用代码字体

- 错: `编辑 mcpp.toml 文件里的 [workspace] 段` → 对: `` 编辑 `mcpp.toml` 里的 `[workspace]` 段 ``
- 完整命令放代码块, 不夹在句子中间. 句子里只引用命令名或短参数: `` 加上 `--locked` 才会读 `mcpp.lock` ``
- 文件名后面不必再补 "文件" 两字, 但配置节, 字段名之类要说清种类: 写 `` 字段 `name` ``, 不写 `name 这个东西`
- 标点放在代码字体外面. 错: `` 运行 `mcpp build,` 然后 `` → 对: `` 运行 `mcpp build`, 然后 ``. 档案 A 同理, 全角逗号也在反引号外面

### 标识符不翻译, 也不在里面夹中文

- 错: `` 运行 `mcpp 构建` `` → 对: `` 运行 `mcpp build` ``
- 错: 把 `--dry-run` 写成 `--试运行`, 把环境变量写成 `MCPP_线程数`
- 错误信息, 日志, UI 的英文原文, 原样放进代码块或粗体, 后面再用中文说明. 不要把原文翻译后当成引用
- 如果产品界面本身有中文, 写界面上的中文, 不要再回译成英文. 界面元素用粗体: `点击 **保存**`. 界面是英文的, 就写英文原文: `点击 **Save**`, 不要译成 "保存"

### 占位符

- 占位符和代码里一致, 用英文大写加下划线, 放在代码块里: `mcpp new PROJECT_NAME`
- 代码块后用中文说明: `PROJECT_NAME 换成你的项目名`. 不要把占位符写成中文放进命令里. 错: `mcpp new <你的项目名>`

## 标题

- 不加序数词和编号. 错: `二、性能问题` → 对: `为什么构建慢`
- 标题末尾不加标点, 两档一样
- 任务标题用动词短语, 概念标题用名词短语: `配置缓存目录`, `缓存的工作方式`. 不写 `如何配置缓存目录` 或 `关于缓存目录的配置`
- 不写中英对照标题. 错: `缓存 (Cache)` → 对: `缓存`. 需要英文, 在正文第一次出现时标注
- 标题里的英文名和代码保持原样大小写, 代码用代码字体: `` ## `mcpp.toml` 的 workspace 继承 ``
- 不用 emoji, 不用问句标题 (`什么是缓存?`), 除非是 FAQ

## 编号步骤与引导句

- 有先后顺序的操作用 Markdown 有序列表, 不手写 `第一步`, `首先 / 其次 / 最后`, `1、`
- 每一步一个动作, 第一句含祈使动词, 省略 `请`, `您`, `你需要`. 错: `请您点击保存按钮` → 对: `点击 **保存**`
- 多数情况下, 步骤前要有引导句, 说明这组步骤要达到什么, 以冒号结尾: `要把缓存挪到 SSD:`. 标题已经说清这组步骤时可以省略, 不要把标题再复述一遍. 不写没有信息的引导句. 错: `请按照如下步骤进行操作:` → 对: `要创建配置文件:`
- 条件放在动作前面. 错: `点击 **保存**, 如果你想保留修改` → 对: `要保留修改, 点击 **保存**`
- 命令放在步骤下面缩进的代码块里, 需要看到的结果写在命令块之后, 一句话
- 步骤结尾的标点按所选档案: 档案 B 不加句号, 档案 A 句末加句号
- 列表项句式并列: 全是动词开头, 或全是名词短语, 不混

## 术语

本节给出判断标准: 哪些词保留英文, 哪些翻译, 以及怎样保持全文一致. 本 skill 不提供固定词表, 下面的词只是例子, 遇到新词按标准逐个判断

### 保留英文的情况

- 产品名, 协议, API 名, 命令行参数, 字段名, 错误信息里出现的词 (读者会搜到它们)
- 业界几乎不翻译的词, 例如 `API`, `commit`, `pull request`, `workspace`, `target`, `Agent` (若项目习惯如此)
- 翻译后会比原词更难认的词, 例如 `vendor hook`, `restricted hook`

### 翻译的情况

- 中文里已经有稳定通用译法, 读者不会去搜英文的词, 例如 `依赖`, `缓存`, `线程`, `内存`, `数据库`, `服务器`, `默认`
- 用大陆通行译名, 不混入台港用法: `文件`, `服务器`, `程序`, `数据库`, `默认`, 不写 `檔案`, `伺服器`, `預設`

### 一个术语只有一个译法, 全文不轮换

- 错: 同一篇里 `配置`, `设置`, `设定` 指同一个东西 → 对: 全篇 `配置`
- 错: `缓存`, `高速缓存`, `cache` 混着用 → 对: 全篇 `缓存`
- 错: `构建` 和 `编译` 当同义词轮换 → 对: 分开用, 各自固定. 构建 (build) 包含链接和打包, 编译 (compile) 只到目标文件
- 动词和名词同形的词 (`commit`): 名词写 `提交`, 动词也写 `提交`, 或者两者都保留 `commit`, 别一个翻一个不翻
- 篇幅较长的文档, 开头放一张术语表, 写明这篇文档保留或翻译的决定, 后文照表

### 缩写和首次出现

- 读者可能不熟的缩写, 首次出现写 `中文全称 (英文缩写)`, 之后只写缩写. 档案 B 用半角括号 `( )`, 档案 A 用全角括号 `（ ）`. `API`, `HTML`, `URL` 这类通用缩写不必展开
- 错: 首次出现就写 `KMI 需要保持稳定` → 对: `内核模块接口 (KMI) 需要保持稳定`
- 不要每次都给括号注释. 错: 每处都写 `缓存 (cache)`

## 数字与单位

- 数量, 版本, 日期, 序号, 范围一律用阿拉伯数字: `3 个文件`, `第 2 步`, `v2.3`, `2026-10-07`
- 固定词语里的汉字数字照旧: `唯一`, `第一次`, `一次性`, `十分`
- 数字与单位之间加空格: `200 ms`, `16 GiB`, `8 核`. `%` 和 `°` 不加
- 版本号写 `2.3 版`, 不写 `2.3版本` 或 `第二点三版`
- 范围用 `到` 或 `-`, 不用 `~`. 错: `10~20个` → 对: `10 到 20 个`
- 技术数值不用 `万`, `亿`, 写千分位数字. 错: `上限 100 万个文件` → 对: `上限 1,000,000 个文件`. 千分位的逗号后面不加空格
- 日期用 ISO 格式 `2026-10-07`, 或 `2026 年 10 月 7 日`, 全文一种
- 不要把 `大约`, `左右`, `若干` 和精确数字叠在一起. 错: `大约 200 ms 左右` → 对: `约 200 ms`

## 引号

- 不用引号标代码, 命令, 文件名, 参数, 用代码字体. 错: `运行 "mcpp build"` → 对: `` 运行 `mcpp build` ``
- 不用引号标界面元素, 用粗体. 错: `点击 "保存"` → 对: `点击 **保存**`
- 引号只用于两件事: 引用别人的原话, 或提到某个词本身
- 不用引号做强调或讽刺. 错: `这个 "方案" 很简单` → 对: 直接删, 或写出为什么简单
- 档案 B 用半角直引号 `"..."`, 外侧与中文之间加空格; 档案 A 用 `“ ”`. 代码里永远是 ASCII 引号
- 引用一整句英文时, 引文里的标点照原句保留, 见 [两档的边界](#两档的边界)
- 文档标题用书名号只在档案 A; 档案 B 用链接文字或粗体

## 机翻腔与 AI 腔

下面每条都是 "错 → 对". AI 腔词表出自作者自己的改稿清单, 只取与技术文档有关的部分, 不涉及作者语气

### 动词名物化和 "进行"

- 错: `对配置进行修改` → 对: `修改配置`
- 错: `对文件进行备份操作` → 对: `备份文件`
- 错: `予以支持`, `加以验证` → 对: `支持`, `验证`

### 被字句和 "可以 / 来"

- 错: `文件会被命令创建` → 对: `命令会创建文件`
- 错: `你可以使用 mcpp 来构建` → 对: `用 mcpp 构建`
- 错: `通过运行 X 的方式得到 Y` → 对: `运行 X 得到 Y`
- `可以` 只在 "允许但不必" 时用. 必须做的写 `必须`, 建议做的写 `建议`, 选项写 `可选`, 不要什么都写 `需要`. 错: `你需要先安装 mcpp` (硬性前提) → 对: `必须先安装 mcpp`; 步骤里直接写 `先安装 mcpp`

### 译文句式和长定语

- 错: `一种能够在低资源环境下稳定运行的轻量级方案` → 对: `方案很轻, 低资源环境下也能稳定运行`
- 错: `对于大型 workspace 来说, 门禁开销较高` → 对: `大型 workspace 的门禁开销高`
- 错: `在使用缓存的情况下` → 对: `启用缓存时`, `如果启用缓存`
- 错: `用户的配置的路径的设置` → 对: `设置配置路径`
- 错: 句首连用 `然而`, `此外`, `同时` → 对: 删掉, 让语序承担关系

### 空泛引导和提示

- 错: `主要有以下几点:`, `原因如下:` → 对: 直接说判断, 如 `构建慢有两个原因: 缓存未命中, 依赖重复下载`, 或者不用列表
- 错: 泛用 `值得注意的是`, `需要注意的是`, `请注意:` → 对: 用固定的 `注意:` 标签, 后面写具体风险和后果, 一处一条
- 错: `接下来我们将介绍如何配置缓存` → 对: 直接开始 `配置缓存`, 或者删掉
- 错: `让我们一起...`, `总的来说`, `综上所述` → 对: 删掉

### 营销词和浅层拔高

- 错: `强大的缓存机制`, `灵活的配置`, `轻松上手`, `开箱即用`, `无缝集成` → 对: 写具体做什么: `缓存按配置指纹分目录存放`
- 错: `赋能开发者`, `底层逻辑`, `闭环`, `抓手` → 对: 写事实: `让开发者少写一层胶水代码`
- 错: `这体现了 X 的重要性`, `为 X 奠定了基础` → 对: 删这半句, 事实说完就停
- 错: `不是 A, 而是 B`, `与其说 A, 不如说 B` → 对: 直接说 B, 除非 A 是上文真有的说法
- 错: `作为核心组件, A 扮演着 X 的角色` → 对: `A 是核心组件`

### 对话残留

- 错: `希望这对你有帮助`, `好问题`, `当然可以` → 对: 删掉
- 称呼读者用 `你`. 错: `您` 和 `你` 混用, `请您` 满篇 → 对: 全篇 `你`, 除非项目规定用 `您`; 步骤里直接省略称呼

### 机翻特有

- 错: 把英文括号里的补充整句硬译, 造成倒装: `它是一个被设计来用于构建的工具` → 对: `它是构建工具`
- 错: 逐词翻译固定搭配: `依赖的解析` → 对: `解析依赖`; `在 X 之下` → 对: `在 X 下`, `X 时`
- 错: `请确保您已经成功地安装了` → 对: `确认已经安装`
- 错: 量词和 "个" 随处加: `一个 API 的调用` → 对: `调用 API`

## 交付前自检

事实和篇幅先于标点. 中文文档不跑检查脚本, 这份清单就是检查

- 事实: 每一句断言 (行为, 默认值, 原因, 范围, 平台) 都能在简报或源材料里找到出处, 找不到就删掉, 或列给作者确认. 源材料里的限定语 (可能, 部分, 通常) 原样保留, 不要改成肯定句, 也不要为了凑字数加没有出处的句子
- 篇幅: 落在简报要求的范围内. 事实写完还不到下限时, 停下来告诉作者实际写了多少字, 缺什么, 不要用重复或编造补足. 不许超过上限, 超了就先删简报之外的内容
- 全文只用一个标点档案, 没有混用. 默认的档案 B 正文里没有全角标点, 半角标点后面跟一个空格
- 档案 B: 段落, 列表项, 表格单元格末尾没有句号
- 档案 B: 没有破折号 (含 `——` 和 ` - ` 当破折号用), 并列项没有用顿号
- 引用的整句英文保留了原句的标点
- 汉字与英文, 数字之间有空格, 代码字体前后也有
- 所有命令, 文件, 路径, 参数, 环境变量, 占位符在代码字体里, 没有中文夹在里面
- 产品名大小写与官方一致
- 每个术语只有一种译法, 首次出现的缩写给了全称
- 标题没有序数词, 没有末尾标点
- 步骤是有序列表, 每步一个动作, 引导句 (有的话) 有信息
- 称呼读者用 `你`, 步骤里省略称呼
- 没有 `进行`, `予以`, `加以`, 没有泛用的 `值得注意的是`, 没有营销词
